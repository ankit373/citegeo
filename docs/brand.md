# Brand and documentation visual standards

Applies to: Phase 6 documentation, the site, and the candidate product, planned for version **v0.2.0-rc.1, UNPUBLISHED**. This page governs how the current brand assets are used. It is not a claim that light/dark themes, browser screenshots, or the candidate image assets have passed acceptance.

## Name and narrative

The product's text name is CiteGEO. The formal vector wordmark stays lowercase **citegeo**, used directly from the existing asset; do not retype its outline with a font substitute.

Headline: **Open the GEO black box. Inspect the evidence.**

Subhead: Enter a domain and see how different AIs describe you, which competitors they name, which keywords they associate, and which sources an answer actually returned. Every comparison traces back to the matching model's original answer.

This boundary must always be kept alongside it: what is published is this run's answer and its evidence; it does not expose the model's internal reasoning, and a rerun is not guaranteed to produce an identical answer.

The narrative centers on the user inspecting samples, conditions, raw answers, and sources. D is called domain recognition, K is called neutral keyword selection; D must not be described as unprompted brand discovery. Never promise guaranteed recommendations, claim to reverse-engineer a model's algorithm, claim to reveal its training sources, claim to read its internal reasoning, claim global uniqueness or unverified optimization results, or make a blanket claim that other GEO products are fraudulent.

*Historical note: the product briefly carried a matching Simplified Chinese headline and a bilingual UI. Both were removed after v0.2.0; the product, its documentation, and this brand guide are English-only in this checkout.*

## Light and dark themes

The site keeps the warm charcoal background `#14120F` and uses the `#F2EEE4` source assets. GitHub's theme is chosen by the reader; the README must not force a black background via CSS. The light theme must use a dark-fill version of the same geometric paths, the dark theme uses the current white version, selected via GitHub's supported picture/source or theme-image markup.

A theme variant may only change the visible fill color. Before it is formally referenced, confirm the actual file exists and that its path, viewBox, and transform are unchanged; do not fill in a Markdown reference to a theme file that has not been generated yet. This document does not create the asset variants; light/dark visibility needs to be accepted separately in the final README and in a real browser.

Superseded logo files were removed; the four files in the table above are the complete current set. Do not reintroduce a retired mark, and do not read any other filename as a theme variant of the current emblem. The [asset notes](../assets/brand/README.md) describe the current set.

## Layout, charts, and readability

The primary visual language is black and white, geometric shapes, and generous whitespace. Documentation is organized with headings, paragraphs, a small number of badges, readable tables, Mermaid diagrams, and real product screenshots; it must not depend on JavaScript, external fonts, arbitrary CSS, or autoplay to be legible. Technical IDs go in evidence entry points, not crowded into marketing headlines.

Color follows [DESIGN.md](../DESIGN.md) and is spent on two jobs that never overlap. Evidence state uses `confirmed` `#7FA06E`, `unknown` `#C9973E`, and `failed` `#B2503B`, and those three appear only to report a state, never to decorate chrome. Chart series identity uses `series-1` through `series-6` (`#6B8CAE`, `#8B7FBF`, `#B98A5E`, `#6FA88A`, `#A6748F`, `#7A94A0`), assigned from the model ID by the character-index mapping in [product-phase5-app.ts](../src/ui/product-phase5-app.ts). That mapping can collide, and the model name and search mode must still stay readable; colors must never be reassigned to make a screenshot look better or to flatter a result.

Success, unknown, failure, partial coverage, and missing data are all distinguished with text or shape as well as color, never by color alone. Per the [methodology](measurement-methodology.md), keep the denominator, raw timestamp, protocol, and search condition visible; show a genuine empty state when there is no data, never a decorative trend line.

## Motion

Follows the existing [Motion Design System](MOTION_DESIGN_SYSTEM.md), [motion-runtime.ts](../src/ui/motion-runtime.ts), and [workbench-style.ts](../src/ui/workbench-style.ts). Common durations: 80ms for press feedback, 140ms for hover/focus, 160ms for content entry, 200ms for a drawer, 300ms for a chart update, 650ms for a line's first draw, and 800ms for success feedback.

This describes the established interaction spec; it is not a claim that every new page already fully reuses the shared runtime. The current Phase 5 pages also have some local CSS/motion implementation; check reduced-motion, keyboard operation, loading/failure states, and the actual code path before accepting it. Motion never generates data, hides a failure, or delays the user's access to the original text.

## Screenshots and public cases

Screenshots may only come from a real candidate build of the product reading an archived response. The model call's original timestamp is preserved; the screenshot's own capture time is recorded separately. Fixtures standing in for a real test, hand-edited HTML or numbers, touched-up images, AI-generated dashboards, and cropping out an error, a denominator, or a search condition that affects the conclusion are all forbidden.

Every image has a meaningful alt text and caption: case, D/K, model/search mode, run time, sample scope, and its evidence entry point. The screenshot index separately records the run/attempt ID, file SHA-256, browser/viewport, candidate digest, page path, trace, and redaction notes; both mobile and desktop must be legible.

The README carries at most one short action recording, from the real product, with a static image and a text description alongside it. A model's original text keeps its original language; a translation or copy edit must never be passed off as the model's answer. Raw material and its redacted public copy each keep their own hash.

This round, R02 currently lacks a real answer and candidate-container screenshot. Do not substitute an old alpha screenshot, and do not use a template image to claim "four demo sets / 40 real screenshots complete."
